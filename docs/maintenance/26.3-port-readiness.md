# Minecraft 26.3 port readiness

Status as of 2026-10-18. This is research for a later port; the supported Chestwise matrix remains Minecraft 1.20.1, 1.21.1, and 26.2. No 26.3 source or build node is introduced by the maintenance branch.

## Toolchain and loader availability

- Fabric's [26.3 developer announcement](https://www.fabricmc.net/2026/09/15/263.html) recommends Loom 1.17 and Gradle 9.6 at the time of publication, and reports stable Fabric Loader 0.19.5. The maintenance branch already uses Gradle 9.8.1 and Loader 0.19.5, but the current Loom/Stonecraft combination still needs a compatible 26.3 upgrade and matrix validation.
- The [NeoForged project listing](https://projects.neoforged.net/) lists NeoForge 26.3.0.90, ModDevGradle 2.0.148, and NeoGradle 7.1.39. The [ModDevGradle breaking-change notes](https://github.com/neoforged/ModDevGradle/blob/main/BREAKING_CHANGES.md) state that one project can enable modding only once for one NeoForge/NeoForm version. Keep an isolated project boundary for loader versions unless a tested build design proves otherwise.
- The official [Forge download page](https://files.minecraftforge.net/net/minecraftforge/forge/) listed Forge 26.3-66.0.11 in the current release feed. Chestwise's Forge 26.2 build is already a dedicated ForgeGradle subproject rather than a regular Stonecutter Loom node. Treat a separate Forge 26.3 project as the conservative starting assumption; confirm against the 26.3 MDK before deciding its exact layout.
- Quilt's Meta API is the source of loader/game compatibility data. A 26.3 client/server smoke will need a compatible Quilt Loader release; do not infer full support from the Fabric artifact or an API listing alone.

## Likely source and resource work

26.3 is not a routine version bump. NeoForged's [26.2 → 26.3 migration primer](https://docs.neoforged.net/primer/docs/26.3/) calls out the GLFW-to-SDL input change, custom text widgets needing text-input focus notifications, and rendering classes moving from Blaze3D to `com.mojang.renderpearl`. Those areas make Chestwise's screen, search focus, GUI rendering, icons, and block rendering high-risk port targets.

The same primer and Fabric's announcement describe recipe/advancement reloadable-registry changes and broader component, world-generation, and registry changes. Chestwise must specifically recompile and test block/entity registration, `RestockSavedData` load/save, packet codecs/registration, recipe transfer, storage adapters, generated resources, and data/loot formats. The current code uses version-specific identifier APIs already, but that does not establish 26.3 compatibility.

Vanilla's [26.3 pre-release notes](https://www.minecraft.net/en-us/article/minecraft-26-3-pre-release-1) report data pack version 119.0 and resource pack version 97.1. The [26.1 release notes](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1) also document Java 25 and changes to world storage. Before certifying the port, test migration and reopen of copied long-lived worlds; do not use valuable production worlds for first-run validation.

## Recipe viewer availability

- The current [JEI files](https://www.curseforge.com/Minecraft/mc-mods/jei/files/all?page=1&pageSize=20&showAlphaFiles=hide&version=26.3) list 26.3 Fabric and NeoForge files, but no Forge 26.3 file was present in the current recent-file listing. Its API/plugin integration must be checked separately for each loader.
- The current [REI files](https://www.curseforge.com/minecraft/mc-mods/roughly-enough-items/files/all) list 26.3 Fabric and NeoForge builds. The current listing did not show a 26.3 Forge build. Verify exact artifacts and Chestwise plugin compile/runtime compatibility at port time.
- Do not claim JEI, EMI/JEMI, or REI support merely because a viewer release exists. Re-certify viewer transfer behavior on the new recipe/registry APIs. EMI's current relationship is via JEMI/JEI compatibility, not a native Chestwise EMI plugin.

## Suggested port sequence and unresolved risks

1. Confirm the exact stable Fabric, Forge, NeoForge, Quilt, Loom, Stonecraft, Stonecutter, Gradle, and Java combination from official release metadata.
2. Add a version node and loader build boundaries without changing the current published support matrix.
3. Port common, client UI/rendering, networking, data, and loader storage bridges in separate reviewable changes.
4. Run clean builds, unit tests, GameTests, artifact audit, dedicated servers, Quilt where viable, and real client/UI tests. Verify an old-world copy upgrades and saves correctly.
5. Reassess viewer integrations only after vanilla recipe loading and the terminal's normal crafting path work.

Highest risks are client input/rendering API changes, recipe/advancement reload lifecycle, long-world data migration, and loader/toolchain alignment. Forge's project layout and 26.3 viewer coverage require confirmation from the relevant MDK/API artifacts. Nothing in this readiness note is a compatibility claim.
