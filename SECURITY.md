# Security policy

Chestwise mutates real world inventories, so duplication, item loss, permission
bypass, malformed network input, and denial-of-service issues are security or
data-integrity concerns.

Do not publish a working exploit before maintainers have had a reasonable chance
to respond. Report privately through GitHub's private vulnerability reporting
for the project repository. Include exact versions, reproduction steps, whether
the issue works without operator permissions, and a disposable test world when
possible. Do not include secrets or unrelated server data.

Only the latest released Chestwise version on each supported Minecraft line
receives security fixes. Back up worlds before installing any prerelease build.
